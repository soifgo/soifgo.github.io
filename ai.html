SoifGo: Short Manual for AI Assistants

Use this page when you cannot open the full reference SOIFGO_AI_CONTEXT.md (complete, much longer). Everything a beginner needs to go from an idea to a running page is here.

0. Rules for you

  • Reply in the same language the user writes in. Keep code, function names and on-screen menu names in English, exactly as written here.
  • Never invent a menu item, a Sub name, a parameter or a feature. If something is not covered here, say you are not sure and point to the Complete User Guide or the docs.
  • If the user gave an idea, even a rough one, do not interrogate them. Build a complete, simple first version, state your assumptions in one line, and refine afterwards. Ask at most one short question, and only if the answer changes the code (for example: Bluetooth, MQTT or API, and which board).
  • If the user has no button yet, always give the full chain in section 3. Never write "just add a button" as a single step.

1. What SoifGo is

  • A free Android app (Android 7.0 or later, no ads). Each button can run one HTML page (HTML, CSS and JavaScript in one file) inside a WebView. Buttons live in pages and folders, 40 buttons per page, and stay saved.
  • The page can talk to hardware and the phone through the bridge window.soifgo: Bluetooth (HC-05, HC-06, JDY-31, Arduino, ESP32, ESP8266), MQTT, HTTP API, phone sensors and the microphone.
  • It is not an app builder: the idea runs inside SoifGo. It does not become a separate APK and cannot be published to Google Play.
  • Buttons are created with the app's menus, never with HTML code. "Classic mode" and "WebView mode" are not app settings: a WebView is simply a button whose Behavior is Browser or HTML File.
  • Not possible: camera, Bluetooth audio devices (headphones, speakers). window.soifgo does not exist in a normal browser.

2. Get the app (if the user does not have it yet)

  • SoifGo is not on Google Play. Do not tell the user to search for it there.
  • Download from APKPure: https://apkpure.com/soifgo/soifgo.saeidmoghadam, or the ZIP: https://soifgo.github.io/soifgo.zip.
  • Before installing, Android asks the user to allow "install from unknown sources" for the browser or file manager that opens the file.
  • SoifGo asks for each permission (storage folder, Bluetooth, microphone) only when it is needed. Details: Privacy Policy.

3. Create the first button (once)

A new project is empty. The order is fixed: folder, then page, then button. The top-left icon is the main menu; its first item switches between Play (run) and Edit (design). SoifGo always opens in Play.

If the user cannot see Button, the folder or the page does not exist yet. Go back to steps 3 and 4.

4. Make the button a WebView (first time only, in Edit)

  1. In Edit, select the button, then top-left menu, then Behavior, then Browser or HTML File.
  2. A Select Behavior dialog shows two choices: Open URL in Browser (a website, not needed here) and Open or Edit Local HTML File in WebView.Html. Choose the second.
  3. A list of sources follows: Create (+) (a default "Hello SoifGo" page), File Explorer (an HTML file from the phone), Sample (built-in examples) and Saved (pages saved earlier in the project). For a first start, recommend Create (+), confirm the name, and finish.
  4. Do not paste code here. This screen is not a code editor.

If the user's screen shows slightly different wording, follow what the screen shows; it is the same feature.

5. Paste the code (every time the code changes, in Play)

  1. Copy the full HTML you wrote.
  2. Top-left icon, then Play. Tap the WebView button. The WebView opens.
  3. Inside the WebView, tap its top-left menu, then Edit. No extra dialog appears. The code editor opens.
  4. In the editor's top-left menu choose Select All and Paste. The clipboard replaces the whole file.
  5. Right after pasting, tap the yellow ✖ at the top. It saves, leaves the editor and returns to the running page, which reloads with the new code. There is no need to wait.
  • Red ✖ in the WebView toolbar closes the WebView. Yellow ✖ in the editor leaves edit mode and shows the result.
  • If a page does not work, the user tells you what they see, and you fix the code. Then repeat this section.
  • Never tell the user to open a file in a text editor on the phone. The built-in editor is the intended path.

6. What you deliver

  • One complete, self-contained HTML file (CSS and JavaScript inside) that the user can paste in one go. Plain HTML, CSS and JS works offline. Avoid external libraries unless the feature really needs one.
  • If hardware is involved, also give the matching Arduino or ESP sketch with the baud rate and the exact text protocol (for example ON\n and OFF\n), so both sides agree. Pair the Bluetooth module in Android Settings first.
  • Then give the user sections 3, 4 and 5 as simple steps in their language, skipping what they already did.

7. Bridge rules (do not guess)

window.soifgo.CallSub('subName', true, arg1, arg2, arg3)
  • The first argument is the Sub name, copied exactly from the table below.
  • The second argument is always true. Never omit it, never pass false.
  • After true, pass exactly the number of arguments listed for that Sub (0 to 3). If a required value is empty, pass ''. Never add extra arguments and never drop a required one: a wrong count can raise an error or close the app.
  • Always guard: if (window.soifgo) { ... }.
  • Every receiver must be attached to window, for example window.html_bluetooth_tx = function(data) { ... };.

<script>
function send(t) {
  if (window.soifgo) { window.soifgo.CallSub('html_bluetooth_rx', true, t); }
}
window.html_bluetooth_tx = function (data) {
  document.getElementById('log').textContent += data + '\n';
};
</script>

8. Limits to remember

  • Sensors are independent: activate only the ones the page uses. The accelerometer gives X and Y only (no Z); the magnetometer gives one single value with no axes. A compass or a 3-axis level cannot be built. A 2-axis tilt level with Move X and Move Y is possible.
  • MQTT and API work only inside SoifGo's WebView. API calls have rate limits: use safe intervals and give the user a Stop button.
  • The Bluetooth device must be paired in Android Settings first. SoifGo's list is the phone's own Bluetooth list.
  • localStorage persists across reloads; wrap it in try/catch. alert, confirm and prompt work natively.
